# Play Along on a phone

Decided November 2026. This says which stack the mobile app uses, why, what is
already in the repository, and what is still unproven.

## The decision

**One codebase: the existing React and TypeScript web app, shipped three ways.**

| Where | How | State |
| --- | --- | --- |
| Any browser | The website | Works |
| Phone home screen, no store | Installable web app (manifest + offline service worker) | Built, checked in desktop Chrome only |
| Google Play and the App Store | The same build wrapped with [Capacitor 8](https://capacitorjs.com) | Projects generated, never built or run |

## Why Capacitor

Everything difficult in this app is audio code written against the Web Audio API:
the strum detector (an AudioWorklet), the chord check (an AnalyserNode spectrum),
the tuner, and a clock that keeps the notes and the sound together. Capacitor runs
that code unchanged inside the phone's own web view. The falling notes are a
canvas, which a web view also draws as is.

What was considered instead:

- **Installable web app only.** Costs nothing and is already done. It cannot be in
  the stores, and on an iPhone it must be installed from Safari's share menu,
  which few people find. Good for testing on your own phone today.
- **React Native (Expo).** There is no Web Audio or canvas in React Native. The
  `react-native-audio-api` library from Software Mansion now covers much of Web
  Audio, including the microphone, an analyser and worklets, so a port is possible.
  It still means rewriting every screen as native views and the highway in Skia,
  and re-testing the detector on a different audio engine. Worth it only if the
  web view turns out not to be good enough.
- **Flutter, or Swift plus Kotlin.** A full rewrite in languages the project does
  not use. No.

## What is in the repository

- `capacitor.config.ts`: app name, app id, and the folder the apps load (`dist`).
- `android/` and `ios/`: the native projects, generated by `npx cap add`. Icons and
  splash screens are filled in. The microphone permission is declared in
  `android/app/src/main/AndroidManifest.xml` (`RECORD_AUDIO`,
  `MODIFY_AUDIO_SETTINGS`) and `ios/App/App/Info.plist`
  (`NSMicrophoneUsageDescription`).
- `src/native.ts`: the only code that knows about the native shell. It makes
  Android's back button follow the app's own history.
- `src/nav.ts`: screens live in the browser history, so Back works the same in a
  browser, in the installed web app and in the Android app.
- `vite.config.ts`: `vite-plugin-pwa` writes the manifest and the service worker.
  It is switched off for the store build (`--mode native`), which needs neither.
- `assets/`: the icon and splash sources. `public/`: the web app's icons.
- Layout: a tab bar at the bottom on a phone, safe-area padding for notches, and a
  tap on the neck counts as a strum where there is no Space bar.

## Running it

You need Node 22 or newer, plus Android Studio (2025.2.1 or newer) for Android
and a Mac with Xcode 26 or newer for iOS. The apps support Android 7 (API 24)
and iOS 15 upwards.

```sh
npm run mobile:android   # build, copy into android/, open Android Studio
npm run mobile:ios       # build, copy into ios/, open Xcode (Mac only)
```

Then press Run in Android Studio or Xcode with a phone plugged in. After changing
web code, run `npm run mobile:sync` and press Run again.

To try it on a phone without any of that: open the deployed website on the phone
and choose "Add to Home screen". The microphone needs https, which GitHub Pages
provides.

To regenerate icons after changing `assets/`:

```sh
npx @capacitor/assets generate --iconBackgroundColor '#1a110d' --splashBackgroundColor '#1a110d'
```

That tool also writes an `icons/` folder and `public/manifest.webmanifest` for
web apps. Delete both: the manifest here comes from `vite.config.ts`.

## Before the first store release

- **App id.** `com.abdullayerezhep.playalong` is a placeholder. It can never be
  changed after the first upload, so settle it first. It appears in
  `capacitor.config.ts`, `android/app/build.gradle` and the Xcode project.
- **Song library.** The hits are chord charts for private practice. A public
  store listing that names commercial songs is a different matter from using the
  app yourself. Decide what ships before publishing.
- **Signing.** A Play upload key and an Apple developer account.

## What is not proven yet

Nothing here has run on a real phone. In order of risk:

1. **iPhone microphone inside the app.** The web view supports `getUserMedia`
   since iOS 14.5, but there are reports of Capacitor apps where the microphone
   stream arrives and the Web Audio analyser reads silence, and of AudioWorklet
   problems in iOS web views. Test this before anything else on iOS: turn the
   microphone on in Settings and watch whether the level bar moves.

   If it fails, the fallback is to capture raw microphone samples natively and
   hand them to the same detector code. `@cantoo/capacitor-audio-capture` streams
   PCM that way. The detector would move out of the worklet string in
   `src/audio/onsetWorklet.ts` into a plain class that both the worklet and the
   native path call. That is a contained change: the rules, charts and screens do
   not touch the microphone directly.
2. **Phone microphones process the sound.** Phones apply noise suppression and
   automatic gain meant for speech. The app asks for all of it to be off; whether
   each phone obeys is unknown. Strum detection thresholds may need tuning per
   platform.
3. **Delay.** Bluetooth headphones add a large and variable delay. Play mode
   measures the delay, but Learn mode is the safer default on a phone.
4. **The Android project has not been compiled.** It is the unmodified Capacitor
   template plus the permission lines, so it should build, but it has not.
